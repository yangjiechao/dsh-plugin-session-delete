# DSH 会话日志永久删除

[English](README.en.md) · MIT · 无运行时依赖、无构建步骤

给 DeepSeek Harness 的会话菜单增加 **“永久删除日志…”**。删除前必须阅读警告、勾选确认并输入 `DELETE`；取消或关闭警告框不会删除任何日志。

> **这是“本地会话日志删除”，不是“隐私一键擦除”。** 当前 DSH 没有通用删除事务接口，本插件只支持经过校验的 JSONL 日志维护路径，不冒充官方删除能力。请先用无关紧要的测试会话验证，重要历史另行备份。

## 兼容性

针对 **DeepSeek Harness 0.2.2-rc.3 / Session format V4** 开发，manifest 限制为 `>=0.2.2-rc.3 <0.2.3-0`。仅适用于 Web GUI 及本地磁盘 JSONL 后端（raw 和 Zstandard）。不支持远程或不可靠锁文件系统、混合编码、旧格式自动迁移、未来格式、子智能体日志、带子会话/分支的父会话。其他 DSH 版本必须重新验证，不要绕过版本限制。

该下限不只是开发环境标签：对比 npm 发布的 `0.2.1-rc.3` 源码，旧版 `SessionPersistenceSnapshot` 没有本插件用于定位并校验实际日志的 `location`，`WorkspaceRegistry` 也没有本插件用于拒绝删除期间重新打开会话的 `workspace/session-unarchiving` 生命周期事件。保留 `0.2.2-rc.3` 下限；它是当前已验证、包含所需契约的版本，不声称这两个能力恰好首次在该 RC 引入。缺少 `location` 时插件会拒绝操作，不会猜测日志路径。

## 安装

下载或克隆 [公开仓库](https://github.com/yangjiechao/dsh-plugin-session-delete)，在 **设置 → 插件 → 添加插件** 中安装本地目录；也可以直接让 Agent 使用：

```text
plugin_manager action=install_bundle target=github:yangjiechao/dsh-plugin-session-delete
```

从本地目录安装：

```text
plugin_manager action=install_bundle target=/absolute/path/to/dsh-plugin-session-delete
```

没有安装脚本，无需额外云端账号。安装后刷新现有 DSH 页面；若提示需重启，以安装结果为准。不要启动另一个 Web 服务来替代当前页面。

## 使用

1. 将目标会话**归档**，切换到另一会话；不要再打开目标会话。
2. 关闭其他共用此数据目录的 DSH 进程。若提示“会话仍在内存中”，保存其他工作后重启当前 DSH，再从归档列表操作，**不要重新打开目标会话**。
3. 在目标会话的 `…` 菜单选择 **永久删除日志…**。
4. 警告框显示捕获的会话标题、准确 ID、日志文件数和估算字节数。检查删除范围。
5. 勾选确认并输入大写 `DELETE`。确认只在当前预览后 2 分钟内有效；日志变化会要求重新确认。
6. 点击删除，等待结果。插件不自动刷新页面，避免丢失其他会话未发送的输入；需要时手动刷新列表。工作区内存索引仍可能保留标题，重启 DSH 后再确认。

**正在加载或运行的会话不会被强行关闭或删除。** 有子会话的父会话需要先处理子会话；不会自动级联。

## 删除与保留

| 数据 | 行为 |
| --- | --- |
| 此会话目录中全部已识别的 canonical 日志 generation | **永久 unlink**，不是移入回收站，不保存日志备份 |
| 旧 generation | 一起删除，避免删除当前文件后旧版日志再次出现 |
| 此会话的 workspace membership | 成功后通过公开 entity API 尝试解除；失败明确提示 |
| 空目录、`session.lock`、小型删除凭据 | **保留**，维持锁 inode；凭据只有 ID、创建/请求时间和文件名，不含聊天正文 |
| 归档 ID、部分工作区内存索引 | **保留**；避免操作其他服务的私有状态 |
| 投影缓存、搜索 SQLite / WAL 及旧页 | **不直接清除**；后续搜索通常会对不存在的日志做逻辑对账，但不是磁盘擦除 |
| 共享图片、上传文件、工具 spill 输出 | **保留**，可能仍被其他会话/分支引用 |
| 用户项目、生成文件、Git worktree | **不删除** |
| 其他会话/分支中的历史副本、导出与备份 | **不删除** |
| Hindsight 等第三方记忆、模型提供方或遥测端已接收的数据 | **不能撤回或删除** |
| 定时任务、投递历史 | **不删除**，请独立管理；保留归档门禁 |

删除文件不是 SSD、文件系统快照或备份中的安全擦除。若你的目标是清除所有隐私副本，**本插件不满足该目标**。

## 安全策略

- 仅接受会话 ID，不接受前端传来的文件路径。
- 用现有 Connection RPC 认证通道，并在 Host 检查 `owner` principal；不暴露匿名 HTTP 删除接口。
- 短期一次性确认令牌绑定当前认证 peer、目标及预览指纹。不会通过 Agent 工具提供删除令牌或确认授权。
- 要求已归档、没有 live Session/Agent；检查已知子会话。
- 路径与 DSH 编码布局一致，拒绝 symlink、junction、hardlink、未知文件和非普通文件。
- 使用持久化后端正常 write-open 获取进程内写排他及跨进程内核锁，锁内重新检查状态和文件身份。
- 保留锁文件及目录，从旧到新删除，当前权威日志最后删除。不使用 `rm -rf`。
- 先写入小型删除意图凭据并同步；出现部分删除时明确失败，不谎称回滚或成功。重新预览后可尝试继续，不会在启动时自动继续删除。
- 从第一次 unlink 开始不因浏览器断线中断有限清理序列；操作失败时状态可能不确定，重新查看，不要盲目连点。
- 在插件存活期间用同步创建门禁阻止同 ID 的并发激活；**这不是跨版本、跨进程的全局 ID 墓碑协议**。

仅在可信本机文件系统、没有其他进程同时改动该数据目录的情况下使用。无法对拥有同一用户权限并恶意换目录的进程提供 OS 级防护，也无法撤销其他进程已取得的历史读取租约。插件卸载后内存门禁不再存在。

## Agent 能做什么

只提供 `session_delete_preview({sessionId})`：只读检查资格、日志数和字节数。**真正删除和确认留在人类 UI 中**，不会因为 Agent 调用了工具就绕过警告框。

## 开发与测试

```sh
npm test
npm run check
npm pack --dry-run
```

测试使用临时目录和合成会话，不接触你的真实聊天数据。核心删除逻辑在 `deletion.js`，认证桥和只读工具在 `index.js`，界面在 `client.js`。

## 验证边界

代码和测试不等同于所有平台已经实测。请查看发布说明中的实际测试记录；未验证的平台、视觉显示、真实跨进程故障及更高版本不应被当作已支持。
